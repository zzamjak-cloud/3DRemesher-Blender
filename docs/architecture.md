# 리토폴로지 엔진 설계

## 0.2.0의 구현 경계

`addon/core.py`는 `bpy`에 의존하지 않는 데이터 계약과 분석을 제공합니다. `RemeshBackend.build_input()`은 설정·메시·가이드·밀도를 `EngineInput`으로 묶고, `RemeshBackend.remesh()`는 독립 Python 엔진의 결과와 품질 정보를 반환합니다. Blender 내장 Remesh나 QuadriFlow를 호출하지 않습니다.

`addon/blender_adapter.py`는 Blender 데이터를 계약으로 변환합니다. `operators.py`는 성공한 결과를 새 Mesh/Object에 적용합니다. 원본 메시 데이터, 변환과 속성은 보존합니다. 실패·취소 시 결과를 적용하지 않습니다.

## 첫 엔진의 처리 순서

1. **유효성 검사**: 정점·면 인덱스, 퇴화·중복 면, 연결 상태와 방향을 검사합니다. 열린 경계는 허용하되 안전하게 처리할 수 없는 입력은 거부합니다.
2. **패치 준비**: 안전한 볼록 사각형은 패치로 유지하고, 나머지 다각형은 귀 자르기 방식으로 삼각형화합니다. 오목 다각형에 단순 부채꼴 삼각분할을 적용하지 않습니다.
3. **특징선 판정**: 열린 경계, sharp/seam 표시, 설정된 면 사이 각도를 기준으로 엣지를 보호합니다.
4. **삼각형 병합**: 보호된 엣지를 넘지 않는 인접 삼각형 후보를 평가합니다. 사각형의 볼록성·형상 품질과 근처 가이드 방향 선호도를 기준으로 결정적인 순서로 묶습니다.
5. **쿼드 생성**: 모든 패치에 면 중심을 만들고 공유 엣지마다 동일한 중점을 사용합니다. 삼각형 패치는 쿼드 3개, 사각형 패치는 쿼드 4개가 됩니다. 공유 엣지를 함께 분할하여 틈이나 T 접합을 만들지 않습니다.
6. **목표 수 비교**: 기본 쿼드 수에 정수 분할 수의 제곱을 곱한 후보 중 목표에 가까운 수를 선택합니다. 목표 미달·초과는 보고하며, 이미 많은 쿼드를 줄이는 기능은 없습니다.
7. **결과 검사**: 쿼드 비율, 경계·비다양체·퇴화 면과 종횡비를 확인하고 결과 및 경고를 반환합니다.

이 방식은 실제 쿼드 출력을 만드는 기초 엔진입니다. 기존 정점 배치를 크게 바꾸지 않아 입력 토폴로지와 패치 모양의 영향을 받습니다. 전역 방향장이나 정수 격자 파라미터화 엔진을 구현한 것으로 설명하지 않습니다.

## 데이터 계약

| 항목 | 의미 |
| --- | --- |
| `MeshData.vertices` | 소스 메시의 오브젝트 로컬 좌표 |
| `MeshData.faces` | 정점 인덱스로 표현한 면 루프 |
| `MeshData.hard_edges` | 표시된 특징 엣지 후보 |
| `RemeshSettings.target_quad_count` | 균일 분할 단계 선택에 사용하는 목표값 |
| `hard_edge_angle_degrees` | 패치 병합을 제한할 면 사이 각도 |
| `GuideCurveData.splines` | 소스 로컬 좌표의 스플라인별 방향 힌트 |
| `symmetry_axes` / `density_values` | 준비된 입력이지만 현재 엔진 미지원; 미적용 경고로 표시 |
| `RemeshResult.mesh` | 새 쿼드 메시 데이터 |
| `RemeshResult.quality` | 목표·실제 개수, 쿼드 비율, 연결성 및 형상 지표 |
| `warnings` / `unsupported_controls` | 결과 해석에 필요한 경고와 적용되지 않은 설정 |

작업 함수는 진행률 콜백과 취소 콜백을 받습니다. 원본 `EngineInput`을 수정하지 않으므로 취소·실패 후에도 같은 입력을 다시 사용할 수 있습니다.

분석의 경계 엣지는 면 하나에 속한 엣지, 비다양체 엣지는 면 셋 이상이 공유한 엣지로 구분합니다. 일반 분석 숫자만으로 공간에서의 모든 면 교차나 전체 다양체 여부까지 판정하지는 않습니다.

## Blender 실행과 자원 제한

GUI 연산자는 Blender 번들 Python으로 `addon/worker.py`를 실행하고 JSON 파일로 입력·진행률·결과를 교환합니다. Blender 데이터 생성은 메인 스레드에서만 수행합니다. 취소, 파일 로드 및 애드온 해제 시 작업 프로세스와 임시 파일을 정리합니다. 결과를 적용하기 전에 원본 씬·오브젝트·메시 및 정점과 면 연결 상태가 같은지 확인합니다. 백그라운드 실행은 동기 경로를 사용하고 통합 검증에서 별도 프로세스 경로도 확인합니다.

Python 스레드 대신 별도 프로세스를 사용하는 이유는 [Blender의 스레딩 제한](https://docs.blender.org/api/main/info_gotchas_threading.html)입니다.

실험 엔진은 입력 정점 20,000개, 면 10,000개, 전체 면 코너 50,000개, 단일 면 정점 256개, 가이드 선분 20,000개로 제한합니다. 출력은 최대 200,000쿼드이며 분할 수는 최대 128입니다. 제한을 넘으면 오류로 알리고 원본을 보존합니다. 대형 스캔 모델의 실용적인 처리 속도는 아직 검증하지 않았습니다.

가이드는 POLY와 샘플링한 BEZIER를 사용하며 닫힌 곡선의 마지막 연결도 포함합니다. NURBS 가이드는 지원하지 않습니다.

## 다음 엔진 단계

- 곡률·특징선·가이드를 결합한 표면 4방향장과 특이점 배치
- 목표 수와 페인트 밀도로 정의한 크기장 및 표면 재표본화
- 정수 격자 파라미터화와 쿼드 추출, 폴리곤 감소
- 대칭 평면의 경계 정합성과 다중 축 처리
- 원본 표면 재투영, 형상 오차 측정, UV·웨이트 전송

게임 모델링 품질은 쿼드 비율만으로 판단하지 않습니다. 표면 오차, 종횡비, 특징선과 가이드 정렬, 뒤집힌 면, 대칭 오차를 함께 측정하고 눈·입·관절은 실제 변형으로 검증해야 합니다.

## 참고 연구

[Instant Field-Aligned Meshes](https://igl.ethz.ch/projects/instant-meshes/)는 방향과 위치를 함께 최적화하는 후속 연구 비교 대상입니다. 현재 엔진은 이 논문의 구현이 아닙니다. [Dual Loops](https://www.graphics.rwth-aachen.de/publication/3/campen_2012_sg_preprint1.pdf)의 관련 연구 정리는 단순 삼각형 변환·분할만으로 좋은 쿼드 레이아웃을 얻기 어려운 이유를 설명합니다. 이 프로젝트의 장기 목표에는 이러한 전역 레이아웃 단계가 필요합니다.
