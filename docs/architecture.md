# 리토폴로지 엔진 설계

## 구현 경계

`addon/core.py`는 `bpy`에 의존하지 않는 데이터 계약과 메시 분석을 제공합니다. `RemeshBackend.build_input()`은 설정·메시·가이드·밀도를 `EngineInput`으로 묶고, 후속 엔진은 `RemeshBackend.remesh()`를 통해 새 `MeshData`를 반환하도록 연결할 수 있습니다. 현재 `remesh()`는 명시적으로 미구현 예외를 발생시킵니다.

`addon/blender_adapter.py`는 Blender 데이터를 이 계약으로 변환합니다. UI와 연산자는 `properties.py`, `panel.py`, `operators.py`로 분리했습니다. 현재 분석은 원본 메시 데이터 기준이며 모디파이어가 적용된 평가 메시를 분석하지 않습니다.

## 입력 계약

| 항목 | 현재 의미 |
| --- | --- |
| `MeshData.vertices` | 소스 메시의 오브젝트 로컬 좌표 |
| `MeshData.faces` | 정점 인덱스로 표현한 면 루프 |
| `MeshData.hard_edges` | sharp 또는 seam 표시가 있는 엣지 후보 |
| `RemeshSettings.target_quad_count` | 목표 쿼드 수, 현재는 입력값만 유지 |
| `symmetry_axes` | 소스 로컬 원점 기준 X/Y/Z 대칭 축 입력 |
| `hard_edge_angle_degrees` | 엔진에 전달할 각도. 현재 곡률·특징선 계산은 미구현 |
| `GuideCurveData.splines` | `REMESH_GUIDE_` Curve의 스플라인별 제어점, 소스 메시 로컬 좌표로 변환 |
| `density_values` | POINT/FLOAT_COLOR의 붉은 채널에 밀도 배율을 곱한 값. 속성이 없으면 빈 튜플 |

가이드는 아직 표면 투영이나 곡선 평가를 수행하지 않습니다. Bezier 핸들, NURBS 가중치와 닫힌 스플라인 정보 등을 엔진용 곡선으로 해석하는 단계는 후속 구현이 필요합니다. 현재 밀도는 값이 클수록 더 세밀한 영역을 의도하는 입력이며, 실제 쿼드 크기장으로 바꾸는 기능은 없습니다.

분석에서 경계 엣지는 면 하나에 속한 엣지, 비다양체 엣지는 면 셋 이상이 공유한 엣지로 별도 집계합니다. 면 루프에서 엣지를 계산하므로 느슨한 엣지, 고립 정점의 연결성, 면 자기 교차와 전체 다양체 여부까지 판정하지는 않습니다.

## 엔진 개발 순서

1. **입력 정규화와 기준 모델**: 비다양체·퇴화·구멍·얇은 영역을 분류하고 유기체 및 하드서피스 검증 자산을 준비합니다.
2. **방향장 계산**: 곡률 방향, 특징선과 가이드 접선을 결합한 표면 4방향장을 계산합니다. 특이점의 위치를 확인할 수 있게 합니다.
3. **크기장과 파라미터화**: 목표 쿼드 수와 페인트 밀도로 크기장을 만들고, 표면을 일관된 격자로 매개변수화합니다.
4. **쿼드 추출과 대칭**: 격자에서 쿼드를 추출하고 대칭 평면의 경계 정합성을 보장합니다. 교차 축과 열린 경계를 별도 처리합니다.
5. **최적화와 Blender 연결**: 결과를 원본 표면에 재투영하고 뒤집힌 면·극단적 종횡비·불필요한 특이점을 줄입니다. 진행률·취소·원본 보존을 추가합니다.

규모가 커지면 네이티브 라이브러리나 별도 작업 프로세스를 검토하되, 데이터 계약과 Blender 어댑터를 분리해 유지합니다. 외부 바이너리 자동 다운로드나 상용 알고리즘의 복제는 이 기반에 포함하지 않습니다.

## 품질 판단

쿼드 비율과 개수 외에도 원본 대비 표면 오차, 뒤집힌 면, 비다양체, 종횡비, 대칭 오차, 특징선 보존, 가이드 정렬 오차를 측정해야 합니다. 눈·입·관절 주변은 실제 변형으로 엣지 루프 품질을 검증합니다.

최초 엔진 구현의 완료 조건은 대표 모델에서 원본을 보존한 새 쿼드 결과 생성, 제약 반영 여부 보고, 목표 대비 실제 개수 표시, 취소·실패 시 중간 데이터 정리입니다. 0.1.0은 이 엔진 완료 조건을 충족한 버전이 아닙니다.
