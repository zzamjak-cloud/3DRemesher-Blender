# 검증 결과

## 미출시 로컬 후속 검증 — 2026-09-20

앞선 로컬 단계에서 Python 단위 테스트 146개가 통과했습니다. 격리된 Blender 5.2.0 LTS에서는 바이너리 입력 worker로 큐브 384쿼드, 가이드 원통 128쿼드, 삼각화된 합성 얼굴 3,456쿼드와 서로 분리된 폐루프 세 개를 확인했습니다. 이 합성 얼굴은 삼각화 이전에 규칙 쿼드 격자가 있던 입력입니다. 결과의 최대 종횡비는 1.78, 전체 엣지 길이 변동계수는 22.4%입니다. `dist/GuidedFaceReview.blend`에 원본과 결과를 나란히 저장했습니다. 이 수치와 146개 테스트는 아래 새 생성기 추가 전의 기록입니다.

다음 단계에서는 기존 쿼드 격자가 없는 두 가지 삼각 구형 두부에 같은 큐브 면의 볼록한 `LOOP` 세 개를 배치해, 입력 삼각 연결과 독립된 눈·입 폐루프를 생성했습니다. 목표 2,400에서는 2,314쿼드(목표 오차 3.58%), 최대 종횡비 4.03, 전체 엣지 길이 변동계수 23.9%, 양방향 표면 표본 거리의 최대값 0.00978을 확인했습니다. 목표 5,000에서는 4,892쿼드, 최대 종횡비 4.83, 변동계수 22.5%였습니다. 격리 Blender 5.2 worker는 원본을 보존했고 `dist/NewFacePatchReview.blend` 및 `dist/NewFacePatchReview-wire-only.png`에서 와이어를 검토했습니다. 이 수치는 앞면의 눈·입 세 루프만 사용한 이전 단계의 기록입니다.

이어 앞면과 양측의 세 큐브 투영면에 눈 둘·입·코·귀 둘, 총 여섯 `LOOP`를 배치했습니다. 독립적인 삼각 입력 두 종에서 목표 5,000에 5,012쿼드, 최대 종횡비 4.85, 양방향 표면 표본 거리의 최대값 0.00696을 확인했습니다. 격리 Blender 5.2 worker가 통과했고 `dist/NewFacePatchReview-six-front.png`, `dist/NewFacePatchReview-six-left.png`, `dist/NewFacePatchReview-six-right.png`에서 정면·좌우 와이어를 검토했습니다. 루프 내부는 쿼드로 채워져 있으며 실제 해부학 형태나 개구부는 아닙니다. 팬형 전이와 폴, 차트 경계의 압축이 남아 있습니다.

서로 다른 삼각 분할을 가진 독립 열린 annular 튜브에서는 목표 256에 256쿼드, 최대 종횡비 1.26, 양방향 표면 표본 거리의 최대값 0.0255를 확인했습니다. `LOOP` 관절 링과 `STRIP` 길이 방향 열을 실제 출력 경로로 확인했고, 별도의 격리 Blender 5.2 worker에서 원본 보존을 확인했습니다. 이 튜브 검사는 몸통에 연결된 팔·다리의 분기와 전이 패치를 포함하지 않습니다.

별도의 사각 축 정렬 단일 닫힌 T형 몸통·팔 입력 두 종에서는 목표 900에 928쿼드, 최대 종횡비 1과 세 `LOOP`를 확인했습니다. 격리 Blender 5.2 `tests/blender_branch_t_worker.py`에서도 928쿼드, 단일 닫힌 컴포넌트, 가이드 세 개, 원본 지문 보존을 확인하고 `dist/BranchTReview.blend`를 저장했습니다. Blender 5.2의 `dist/BranchTReview-front.png`, `dist/BranchTReview-side.png`, `dist/BranchTReview-oblique.png`를 검토했습니다. 정면·측면의 격자가 일정하고 겨드랑이 모서리에 5가 폴 네 개가 있으며, 명백한 접힘은 보이지 않았습니다. 이는 직각 사각 T형의 시각 확인이며 인체 곡면이나 3D 자기교차 판정의 증거는 아닙니다. 원형 팔과 실제 캐릭터의 겨드랑이 전이는 미검증입니다.

## 비교 데모

`dist/3DRemesher_Prototype.blend`에 원본 삼각형 1,280개와 결과 374쿼드를 나란히 저장했습니다. 목표는 256개이며 형상 보존 때문에 46.1% 초과했습니다. 최대 표면 편차 0.027183, 평균 0.007515, 최대 종횡비 4.622, 평균 1.395입니다. 경계·비다양체 엣지·퇴화 면은 모두 0입니다.

데모 생성 프로세스는 종료 코드 0이지만 Blender 종료 시 약 0.023 MB의 미해제 메모리 진단이 나왔습니다. 원인은 분리하지 않았습니다.

## 설치용 산출물

- 파일: `dist/zzamjak_3d_remesher-v0.3.0.zip`
- 배포본 크기·SHA-256: [v0.3.0 Release의 ZIP 및 SHA256SUMS](https://github.com/zzamjak-cloud/3DRemesher-Blender/releases/tag/v0.3.0)
- 포함: manifest, GPL 전문, 루트 등록 모듈, `addon/*.py`
- 제외: 개발 스크립트·테스트·문서·CI·캐시

재빌드 시 ZIP 메타데이터 때문에 해시가 달라질 수 있습니다.

## 배포 검증

Linux CI에서는 Blender 4.2.0과 5.2.0으로 등록·worker·수용 검사를 실행합니다. 릴리스는 해당 검사를 통과한 ZIP을 게시하며, Pages 인덱스의 크기와 SHA-256을 ZIP과 대조합니다. [Actions 실행 결과](https://github.com/zzamjak-cloud/3DRemesher-Blender/actions)와 [배포 인수 절차](distribution.md)에서 확인할 수 있습니다.

배포 인수 스크립트는 일상 프로필과 분리한 새 프로필에서 원격 신규 설치 및 0.2.0 → 0.3.0 업데이트를 실행합니다. 설치 버전·활성화·시작 시 업데이트 확인 설정·worker·64쿼드 생성·원본 보존 결과를 `dist/distribution-verification.json`에 기록합니다.

## 미검증 범위

- Windows 런타임. Windows 실행기는 BOM, 인자 전달, Junction 보호와 종료 코드 전달을 정적으로 검사했습니다.
- 사용자 제공 캐릭터의 눈·입·관절 루프와 실제 리깅·애니메이션 품질.
- 대형 스캔 입력의 실용적인 처리 시간. 선언된 입력·출력 상한은 성능 보장이 아닙니다.
- 일상 사용자 프로필은 변경하지 않았습니다. 원격 설치·업데이트 인수 검사는 별도 프로필을 사용합니다.

UV·스킨 웨이트·셰이프 키 전송, NURBS 가이드, 모디파이어 평가 결과의 리메시는 이번 구현 범위에 포함하지 않습니다.
